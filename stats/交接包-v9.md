# 分組求生記 v9 交接包：Apps Script 更新

作者：may22 ・ 2026-11-13

## 這次要做什麼
遊戲 v9 已上線（https://iammay22.github.io/group-survival/），新增「最新戰報」和開始畫面的 LIVE 跑馬燈。
試算表端要配合兩件事：
1. 回傳**最近 5 局**的成績（給戰報和跑馬燈用）。
2. 把遊戲新送來的 **`title`（稱號）** 記進「原始資料」。

## 要改哪裡

| 檔案 | 動作 |
| --- | --- |
| 「排名功能」 | **整段換成** 交接包裡的 `排名功能.gs` |
| 原本的程式碼檔（Code.gs／程式碼.gs） | **刪掉** `function doPost(e) { … }` 整段；若還有 `doGet` 也刪掉 |
| 部署 | 部署 → 管理部署作業 → 鉛筆 → 版本「新版本」→ 部署（網址不變） |
| setup | **不要執行**（會覆蓋自訂的統計版面） |

為什麼要刪原本的 doPost：新的 doPost 在「排名功能.gs」裡，Apps Script 不允許兩個檔案有同名函式，留著會不知道跑哪一個。

## 新版「排名功能.gs」相對於你目前版本的差異
保留你版本的：`?action=scores`、`?nocache=1`、`avg`、錯誤時回傳 JSON、標題去空白、`testScoreDist`。

新增：
- **doPost**：依「欄位名稱」寫入，不依欄位順序，你在原始資料調換或新增欄位也不會寫錯欄。第一次收到稱號時，會自動在最右邊補上「稱號」欄標題。
- **recent**：`doGet` 回傳裡多了 `recent`（最近 5 局，由新到舊）。
- 快取：分布 `scoreDist_v1` 5 分鐘；戰報 `recent_v1` 1 分鐘，而且每有一局完成就清掉，所以戰報幾乎是即時的。

## 回傳格式（遊戲依賴這個格式）
`GET <網址>?scores=1`

```json
{
  "n": 304, "avg": 86.1, "updated": "2026-11-13T08:20:00.000Z",
  "hist": [[30, 1], [37, 1], [99, 36], [100, 21]],
  "recent": [
    {"t": 1794550000000, "grade": "A+", "score": 98, "size": 5, "topic": "在地小吃紀錄片", "title": "通靈組長"}
  ]
}
```
- `hist`：[分數, 局數]，只算 `事件 = finish`、排除 `版本 = test`。
- `recent[].t`：毫秒時間戳記；`title` 舊紀錄為空字串，遊戲會顯示成【分組倖存者】。

## 遊戲送來的欄位（doPost）
`event, sid, grade, score, size, topic, progress, mood, coverage, quits, device, version, source, ref, title`
對應原始資料欄位：時間、事件、玩家代號、成績、總分、人數、題目、報告進度、組內氣氛、專長完整度、退組人數、裝置、版本、來源、來源網域、稱號。

## 怎麼確認成功
1. 編輯器選 `testScoreDist` → 執行，執行記錄應出現 `recent` 陣列。
2. 瀏覽器打開 `<網址>?scores=1&nocache=1`，應看到含 `recent` 的 JSON。
3. 去遊戲玩一局：結算畫面「最新戰報」會出現自己這局以外的紀錄；開始畫面上方會出現 LIVE 跑馬燈；原始資料最右邊出現「稱號」欄。

## 隱私
對外只回傳匯總分布和最近 5 局的時間、等級、分數、稱號、人數、題目；不回傳玩家代號、裝置、來源。
